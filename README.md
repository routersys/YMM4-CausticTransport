# 光輸送結像 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-CausticTransport.svg)](https://github.com/routersys/YMM4-CausticTransport/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、現在のフレームの明るさを光の分布として輸送格子へ集め、選択した光源形状へ広げた光を元映像へ結像させる映像エフェクトプラグインです。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
結果は入力映像と設定から決定論的に決まり、同じ環境と設定では常に同じ結果になります。
面、円、横スリット、縦スリットの4種類から光源形状を選択できます。
強さ、集光度、光源サイズ、分散、面粗さの5項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「光輸送結像」として表示されます。カテゴリは加工と装飾です。

入力された現在のフレームから各画素の明るさを求め、輸送格子の上に光の分布として集めます。処理する範囲は、このエフェクトに入る映像を囲む矩形です。輸送格子は、この範囲を縦横に区切ったセルの並びです。輸送写像は、光の分布を、選択した光源形状が定める目標分布へ移す対応づけです。この対応づけは、ポアソン方程式を解く反復で求めます。

光の分布を集めた後の処理は、3つの段階に分かれます。輸送の計算は、輸送写像を求める段階です。描画は、輸送写像に沿って各画素の色と不透明度を動かし、光の像を作る段階です。合成は、光の像と入力映像を強さの割合で混ぜる段階です。集光度は、描画で画素をどれだけ動かすかを決めます。集光度が0%のときは光を光源形状へ広げ、100%のときは入力映像をそのまま出力します。分散は赤、緑、青の移動量に差を付けて色を分け、面粗さは輸送写像にずれを加えて光の筋を柔らかくします。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへ画素を読み戻さず、入力映像の変化の判定に使う2個の整数だけを読み戻します。入力映像、品質、光源形状、光源サイズが変わらないフレームでは、輸送の計算を再利用します。集光度、分散、面粗さ、シードも変わらなければ、描き直しません。再利用の条件は「注意事項」にあります。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-CausticTransport/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「光輸送結像」を選択してください。

## 主な機能

### 1. 光の分布の輸送

現在のフレームの各画素について、不透明度を掛けた色のBT.709の輝度に、不透明度の1%を足します。この値を各画素の明るさとし、輸送格子のセルごとに合計して光の分布を作ります。この分布と、選択した光源形状が定める目標分布を、同じ総量へそろえます。外部マスクや手動の位置指定は必要としません。

最初の輸送写像は、面では各セルを動かさない写像、円では範囲を円形へ写す写像、スリットでは範囲を帯へ一様に縮める写像です。この写像から、次の3つの処理を品質が定める回数だけ繰り返します。まず、光の分布を輸送写像に沿って動かします。次に、動かした分布と目標分布の差を求めます。この差が右辺になるポアソン方程式を解き、その解をポテンシャルとします。最後に、ポテンシャルの勾配に沿って輸送写像を更新します。

ポアソン方程式は、マルチグリッド法のVサイクルで解きます。マルチグリッド法は、セルを2×2ずつまとめて粗くした格子を重ね、粗い格子の解を細かい格子へ引き継ぎながら解く方法です。Vサイクルは、まず右辺の差を粗い格子へ順にまとめます。次に、粗い格子で解を求めます。その解を細かい格子へ順に引き継ぎ、各格子でJacobi反復を行って解を整えます。Jacobi反復は、各セルの値を、上下左右の隣のセルの直前の反復での値と、そのセル自身の右辺から計算し直す操作です。この操作を、全セルで同時に行い、繰り返します。輸送写像の反復回数と、Vサイクル1回につき各格子で行うJacobi反復の回数は、「品質の選択」の表にあります。

### 2. 集光度による描画と結像

集光度は、求めた輸送写像に沿って画素をどれだけ動かすかを決めます。画素は、元の位置から輸送写像の移動先へ向かう道のりのうち、100%から集光度を引いた割合だけ動きます。たとえば集光度が25%なら、道のりの75%まで動きます。分散を上げたときの色ごとの違いは、「分散による色分け」にあります。集光度が0%のとき、画素は輸送写像の移動先まで動き、光は光源形状の分布へ広がります。集光度が100%に近づくほど画素は元の位置に近づき、光は入力映像の形へ戻ります。この戻った状態を結像と呼びます。

描画では、各画素の色と不透明度を、動かした先の位置を囲む4画素へ、位置に近い画素ほど多くなる割合で分けて足し込みます。足し込む順序によらず同じ結果になるよう、値を整数に直して集計します。足し込んだ先の画素で不透明度の合計が100%を超えるときは、色と不透明度を不透明度の合計で割ります。この画素の不透明度は100%になり、色は重なった色を不透明度で重み付けした平均になります。描いた光の像は、強さの割合で入力映像と混ぜて出力します。

集光度をアニメーションで変えると、光源形状へ広がった光から入力映像が立ち上がる遷移や、入力映像が光源形状へ崩れる遷移を作れます。

### 3. 光源形状と光源サイズ

光源形状は、集光度0%で光が広がる目標分布の形を決めます。面は、処理する範囲の全体へ光を一様に広げます。円は円形に、横スリットは水平の帯に、縦スリットは垂直の帯に光を集めます。円とスリットの位置は処理する範囲の中央に決まっており、ずらすことも、斜めに傾けることもできません。

光源サイズは、円の直径とスリットの帯の幅を決めます。100%のとき、直径と帯の幅は処理する範囲の短辺と同じ長さです。面では光源サイズを使いません。円とスリットの縁はぼかします。

### 4. 分散による色分け

分散は、赤、緑、青の3色で移動量を変えます。緑は集光度が決める基準の移動量で動かします。赤は緑より遠くへ動かしますが、輸送写像の移動先を越えることはありません。青は緑より手前までしか動かしません。この移動量の差で、光が広がる途中では赤と青の縁が分かれ、色が虹色にずれます。赤の移動量は最大で緑の(1+0.35×分散)倍、青は(1-0.35×分散)倍です。分散が100%のとき、赤は最大で1.35倍、青は0.65倍です。分散を0%にすると、3色を同じ移動量で動かします。

赤が輸送写像の移動先で止まるため、分散が100%で集光度が約26%を下回ると、赤の移動量は緑の1.35倍に届きません。分散が0%より大きければ、集光度が0%のとき赤と緑は同じ位置へ動き、青だけが手前に残ります。分散が0%より大きいとき、不透明度は3色に3分の1ずつ分け、それぞれの色と一緒に動かします。

### 5. 面粗さによる散乱とシード

面粗さは、輸送写像にセルごとのずれを加えて、光を散乱させます。面粗さを上げると、光の筋が磨りガラスのように柔らかく散らばります。ずれの向きと大きさは、シードとセルの位置から作るハッシュで決まります。ずれの大きさは、面粗さが100%のとき、縦と横のそれぞれで最大0.5セルです。セルの大きさは「品質の選択」にあります。このずれにも、輸送写像と同じ割合を掛けます。この割合は、緑では100%から集光度を引いた値です。赤と青の割合は、緑の割合に「分散による色分け」の倍率を掛けた値で、赤は100%で止まります。面粗さを0%にすると、ずれを加えません。

シードは、散乱の分布を決める固定値です。同じシードと同じパラメータでは、常に同じ散乱になります。面粗さが0%のとき、シードは結果に影響しません。

### 6. 品質の選択

品質は、輸送格子の解像度、輸送写像の反復回数、ポアソン方程式を解くJacobi反復の回数をまとめて切り替えます。

| 品質 | 格子解像度 | 輸送写像の反復 | Jacobi反復 |
|---|---:|---:|---:|
| 標準 | 128 | 4回 | 12回 |
| 高品質 | 192 | 6回 | 16回 |
| 最高品質 | 256 | 8回 | 20回 |

格子解像度は、輸送格子の長辺のセル数の上限です。短辺のセル数は、処理する範囲の縦横比に合わせて決めます。処理する範囲の長辺が格子解像度以下のときは、長辺の画素数がそのままセル数になります。そのため、長辺が128画素以下なら、格子の大きさはどの品質でも同じです。違うのは反復の回数だけです。1セルの幅と高さは、処理する範囲の幅と高さを、それぞれ輸送格子の横と縦のセル数で割った長さです。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 光の像の計算には現在のフレームの色と不透明度だけを使用します。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 処理する範囲の辺が8192画素以下、かつ総画素数が11184810以下の入力に対応します。3840×2160と4096×2160はこの条件を満たし、6000×4000は総画素数が上限を超えます。判定には、プロジェクトの解像度ではなく、処理する範囲の大きさを使います。条件を満たさない入力には、エフェクトを適用せず入力映像を表示します。
- 光は処理する範囲の外へは広がりません。範囲の端へ向かう光は、端の画素に集まります。
- 処理量とGPUメモリ使用量は入力映像の画素数に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は格子解像度と反復回数が最も多いため、高品質と標準より処理負荷が高くなります。
- キャッシュ: 入力映像とその大きさ、品質、光源形状、光源サイズが変わらないフレームでは、輸送の計算を再利用します。光源形状が面のときは、光源サイズを変えても輸送の計算を再利用します。光の分布と、変化の判定に使う2個の整数は、毎フレームGPUで求めます。2個の整数は、全画素の色と不透明度から作ります。この整数と入力映像の大きさが、輸送を計算したときと同じなら、輸送の計算を再利用します。動画のように、直近に読み戻した2フレーム分の整数が違うあいだは、入力映像が変わり続けているとみなします。このときは、今のフレームの整数の読み戻しを待たず、毎フレーム輸送の計算をやり直し、整数は次のフレームで読み戻します。変化が最後に起きたフレームの次のフレームでも、直近に読み戻した2フレーム分の整数はまだ違います。そのため、このフレームでも輸送の計算をやり直し、その次のフレームから再利用します。光源形状が円かスリットのときに光源サイズをアニメーションで変えると、輸送の計算を毎フレームやり直します。入力映像が変わり続けるときと、光源サイズを動かすときは、処理が重くなります。
- 描き直し: 集光度、分散、面粗さ、シードが変わらず、輸送の計算も再利用するフレームでは、描画も再利用します。面粗さが0%のときは、シードを変えても描き直しません。集光度、分散、面粗さ、シードのどれかだけを変えたフレームでは、輸送の計算は再利用し、描画だけをやり直します。強さだけを変えたフレームでは、描き直さず、合成の量だけを変えます。
- 集光度100%と強さ0%: 集光度が100%のときは輸送の計算も描画も行わず、入力映像をそのまま出力します。強さが0%のときも入力を変更しません。
- シードと再現性: 散乱は、シードとセル位置から決定論的に算出します。時間値は散乱の生成に使用しません。面粗さが0%のとき、シードは結果へ影響しません。
- 透明部分: 光の像は、色と不透明度をまとめて移動先へ動かして作ります。完全に透明な画素は動かしませんが、その位置へほかの画素から移ってきた色と不透明度は描かれます。内容が移って空いた位置は、ほかから何も移ってこなければ透明に近づきます。出力の不透明度は、色と同じく、入力映像と光の像を強さの割合で混ぜた値です。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。更新の確認で起きた例外は、更新情報の取得の失敗を除いて報告し、YMM4へは渡しません。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、処理する範囲の辺が8192画素を超えるか、総画素数が11184810を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | manjubox.netとGitHubのどちらへも接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避します。次にYMM4を起動したあと、本プラグインのエフェクトを生成するか、同じくYMM4-Telemetryで報告する別のプラグインが動き始めると、退避した報告を1回の起動で10件まで送り直します。送信も再送も非同期に行うため、通信を待って起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
